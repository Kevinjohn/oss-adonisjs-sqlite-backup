# Capability coverage

All ten stories are existing stories retained at their original paths; no new story was needed. “Existing” denotes a previously documented action, not a runtime test result. Inventory covers Ace commands (`db:backup` and `db:upgrade`), public service and standalone classes, configuration, provider setup, filesystem and database operations, examples, tests and README limitations.

Ace rejects an unknown `operation` argument and a flag used with the wrong operation. Only verify and restore preparation take a bundle name, only restore preparation takes a target, only prune takes a keep count, and only list, verify and restore preparation accept a directory override. [Ace dispatch](../commands/db_backup.ts)

The [package exports](../index.ts) expose the archive, operator and configured backup classes, error classes and types. The [source map](REFERENCE.md) links their consuming operations. The [packed consumer fixture](../bin/packed_consumer_fixture.mjs) exercises package integration, and the [crash suite](../tests/crash.spec.ts) covers interrupted archive operations.

The configured source resolver and startup probe support setup and create (US-SETUP-01 and US-INT-01); `SqliteBackup.prepareDirectory()` and `BackupArchive.prepareDirectory()` prepare archive roots. Internal file syncing supports durability and the internal upgrade path resolver supports US-OP-06. Types, error classes and filesystem helpers are supporting interfaces, not separate user outcomes. The host owns scheduling and live cutover; neither is a package action.
